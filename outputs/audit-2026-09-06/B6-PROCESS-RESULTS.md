# B6 第二切片 — 启停脚本进程身份（A19）

日期：2026-09-07。本切片源码和隔离验证完成，未提交/推送、未部署或重启当前服务。只修复本机启停功能，不增加网络/数据安全框架。

## 已修复

- 不再用 `uvicorn app.main:app`、`--port 800` 的两个子串判断归属，避免另一项目和 800/8001 端口前缀误判。
- 启动显式传入本项目绝对 `--app-dir`。规范化项目目录和端口后，记录完整命令、进程启动时间、解释器、项目、监听地址与完整端口。
- 数字 PID 文件格式不变，旁边新增 `<pid-file>.identity.json`。身份记录使用同目录临时文件原子替换，写入失败不损坏原身份文件。
- 新增标准库辅助程序 `scripts/service_identity.py`；它只读进程和写身份记录，不发送信号、不访问网络，不要求安装新依赖。
- 校验完整启动命令后缀，再核对解释器路径，支持项目路径带空格；当前命令和启动时间还必须与原记录完全一致。
- `start/status/stop/restart` 共用该核对。旧 PID、缺失/损坏身份、项目/端口/解释器/出生时间错配时拒绝自动接管或终止。
- 拒绝 0、1、负数、非数字和超大 PID，避免把它们传入信号操作。
- 平滑停止失败、准备强制停止前，再次核对身份。等待期间身份已变化则不强制终止；发送强制信号后也等到确认退出才报告成功并清理本次 PID/身份。
- 启动健康检查失败时，不终止身份无法确认的进程；若已确认属于本次启动，发出平滑停止后仍未确认退出，就保留 PID/身份以便后续处理。
- 清理本次 PID 文件前再次检查文件仍指向本次 PID，不自动删除业务文件。

## 升级与范围

- **旧版仅有数字 PID 的活跃服务不会自动接管。** 应在升级前按原启动方式停止，或先人工核对原进程。不能仅移除 PID 文件来绕过现有实例。
- `start.sh` 与新增辅助程序需一并保留，完整 GitHub 项目已包含二者；macOS `.app` 使用独立启动器，本切片没有改其启停路径。
- 无法查询进程、解释器环境缺失或身份无法确认时，宁可报告拒绝，不把未知状态当作可终止。
- 本切片不新增多实例协调框架。B3 的运行目录/profile 锁继续有效；不把本机 PID 核对描述为分布式进程管理。
