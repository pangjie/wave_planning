# 波次自动化工具

本地运行、可整体拷贝部署的 WMS 工具集，由两个深度整合的部分组成：

1. **波次规划工具**（单文件 HTML）：订单 Excel 导入 → 渠道/分段规划 → 含波次号的 Excel 导出；
2. **WMS 自动化后端**（FastAPI + Playwright）：在浏览器中自动完成「订单导出（全量分析）」「生成波次」「打印波次」「批量拣货」四类生产工作流。

两者合并在同一个控制台页面（`http://127.0.0.1:8000/`）中使用：规划页提交任务，后端用持久化 Chrome 会话操作 WMS，结果自动回填到规划页并给出下载链接。

## 功能一览

### 规划页

- **导入 / 导出**：通过顶部操作区选择订单 Excel（「出库单」工作表），导出含 9 个工作表的波次规划 Excel；其中「客户统计」按实际导出的订单汇总客户订单量、拣货件数、激活 SKU、单件/多件/混件数量，以及各已识别渠道的订单数和占比；
- **实时概览**：总订单、已选择订单、有效波次与活跃渠道在规划过程中同步更新；
- **渠道模式**：在左侧编排控制台切换拆分（按物流渠道）与归并（CBT / CBS / 普通）；
- **浏览器模式**：在左侧编排控制台切换有头 / 无头，决定后端任务用哪种浏览器；
- **主题**：光耀紫府（默认）/ 黄天当立 / 蟠青丛翠 / 万丈红尘 / 海晏河清，点击即换、不重载、不影响任务；
- **分段勾选与参数**：渠道/分段逐项勾选（否掉），分组参数统一或按渠道调整。

### WMS 联动区（四个工作流 + 一个执行按钮）

1. **全量分析**：WMS 导出全部订单并自动导入规划页；
2. **生成波次**：按勾选分段顺序逐段执行——粘贴出库单号精确搜索 → 核对「待处理+已取消」数量 → 全选 → 生成波次（排序规则：库位、SKU*数量）→ 提取波次号，逐段回填并变绿，最后自动导出含波次号的 Excel；
3. **打印波次**：按波次号生成拣货单 PDF 并合并；
4. **批量拣货**：对待拣货波次批量执行拣货。

操作方式：点选一个功能（高亮）→ 点「开始任务」；运行中按钮变为「取消任务」；任务结束恢复「开始任务」。未选功能时按钮不可用。

## 快速开始

### 方式一：完整控制台（推荐）

```bash
cd wms/project
./scripts/setup.sh     # 首次：创建 .venv 并安装后端依赖
./scripts/start.sh     # 启动服务（默认监听 127.0.0.1:8000）
```

浏览器打开 <http://127.0.0.1:8000/>。首次使用建议把「浏览器模式」切到有头，在自动弹出的 Chrome 中登录 WMS，之后切回无头即可复用会话。

### 方式二：纯离线规划

直接双击 `波次规划工具.html`，导入订单 Excel 即可完成规划与导出；WMS 联动区自动隐藏。

## 部署

### 部署准备

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | macOS（推荐）/ Linux | 脚本按 POSIX 编写；Windows 需自备等价环境 |
| Python | 3.11+（推荐 3.12） | `setup.sh` 用它创建虚拟环境 |
| Google Chrome | 已安装 | Playwright 使用系统 Chrome（`channel: chrome`） |
| qpdf | 可选 | 仅「打印波次」合并 PDF 需要：`brew install qpdf` |
| Node.js | 可选（仅构建/测试） | 修改页面后构建、运行规划页测试时需要 |
| 网络 | 可访问 `wms.xlwms.com` | 生产操作依赖 |
| WMS 账号 | 可登录 | 首次有头模式登录一次，会话保存在浏览器 profile 中 |

### 依赖安装

```bash
# 后端依赖（自动创建 .venv）
cd wms/project && ./scripts/setup.sh

# 打印波次需要 qpdf（macOS）
brew install qpdf
```

`setup.sh` 若检测不到 qpdf 会给出提示；不影响除打印外的其它功能。

默认只安装 `backend/requirements.txt` 中的运行依赖；开发测试使用
`./scripts/setup.sh --dev`（读取 `requirements-dev.txt`，复用同一份运行依赖）。
桌面打包使用 `desktop/requirements-build.txt`，也复用运行依赖，不另设版本副本。
所有现有固定包版本保持不变，不会自动卸载旧环境里已有的测试包。

脚本在安装前检查 Python 3.11+，安装后执行依赖兼容性检查，失败不会提示安装完成。
本轮实际回归环境为 Python 3.12.14；其他 Python 版本及另一台 Mac 的全新安装未实机验收。
首次创建可用 `PYTHON_BIN=python3.12 ./scripts/setup.sh` 指定解释器；已有 `.venv`
会直接复用其解释器，不会被 `PYTHON_BIN` 覆盖或自动重建。环境损坏/版本过旧会停止并提示。
更新已有环境前请先正常停止服务；不要复制其他机器的 `.venv`，也不要在服务运行中安装依赖。

### 部署过程

1. **整体拷贝**：把本文件夹完整拷贝到目标机器（所有脚本均用相对路径，无开发机绝对路径引用）；
2. **构建/部署页面**（若拷贝后缺失或改过页面）：

   ```bash
   cd planner && python3 build.py
   ```

   该命令同时生成顶层 `波次规划工具.html` 并部署到 `wms/project/frontend/dist/index.html`；
3. **安装依赖**：`cd wms/project && ./scripts/setup.sh`；
4. **检查配置**：`wms/project/config/automation.json` 中的 WMS 页面选择器、超时、每页条数（1000条/页）等，一般无需修改；
5. **启动服务**：`./scripts/start.sh`（可带端口参数：`./scripts/start.sh 9000`）；
6. **验证**：`curl http://127.0.0.1:8000/api/health` 返回 `{"status":"ok"}`；
7. **登录 WMS**：浏览器模式切「有头」→ 在页面发起一次「全量分析」→ 弹出的 Chrome 中登录 → 登录完成后任务继续，之后可切回「无头」。

### 部署注意事项

#### 定时截单

标题栏“定时任务”切换右侧配置页，不清空当前规划。仅提供一个每日截单任务，默认停用；配置截单时间、提前量（默认 30 分钟）和 IANA 时区后保存。时区必须与 WMS 页面创建时间一致。首次启用/修改从下一完整预导出时段开始，不立即补跑。停用阻止后续计划，不中断已经开始的本次任务。

范围固定为截单时间往前 **一周** 的待处理订单。例：10 月 27 日 07:00 截单，06:30 预导出创建时间 10 月 20 日 07:00 至 10 月 27 日 06:30 的订单；07:00 增量导出 06:29:30 至 07:00，重叠 30 秒。两次均通过 WMS 创建时间筛选、回车提交并回读校验，复用原导出模板、任务识别和下载流程。按一行一单、出库单号去重，增量整行覆盖预导出重复订单；不追踪预导出后取消的订单。空订单号、单份文件重复订单、模板字段不一致或文件回读不一致均停止发布。动态 SKU 列允许扩展，最终文件包含用于规划的“出库单”sheet，不合并其他辅助 sheet。

后台只导出及合并，不分析、不自动替换规划。日志中的截单文件链接为“点击加载分析”，另有独立下载入口；打开/刷新页面恢复最近执行摘要和链接，但不自动加载。点击后使用当前网页设置分析，已有规划时先确认替换，生产任务运行中禁止加载。截单时刻是增量导出启动时间，不保证该秒文件已完成。

调度跟随现有后端生命周期，无系统定时服务、Node.js、唤醒或防休眠机制；合并使用项目 Python 环境中的 `openpyxl`（更新后执行 `pip install -r backend/requirements.txt`）。Mac 必须醒着、服务运行、WMS 登录及网络有效。浏览器由原任务互斥控制，占用时等待且显示延迟。未开始预导出就已经错过截单时间的任务标记为错过，不自动补跑；已启动任务的延迟阶段保持原时间范围。夏令时不存在的时刻跳过，重复时刻只取第一次。

配置、执行状态和日志保存为 `wms/project/data/cutoff-schedule.json`；每次的原始预导出、增量、最终文件位于 `wms/project/downloads/scheduled/<执行ID>/`。这些是本地运行数据，不应提交 Git。执行结果保留，配置页列出最近 30 次，侧栏摘要最近 5 次。失败可手动重试失败阶段；已确认任务身份时只等待/下载原任务，不重复提交。若提交后未确认任务身份，拒绝盲目重试，需人工核对。服务重启后的中断导出保留记录，显示失败后可按上述规则重试。

#### 日常任务

普通全量导出在提交前重置 WMS 查询条件并选择待处理，防止继承上一次定时任务的增量时间范围；它不使用定时截单的一周范围。

打印波次清单留空（含只有空白字符）时，自动选择当前规划中已勾选且已有确认波次号的“单件”和“混件”，按当前波次表顺序提交并去重，不包含“爆品”和“多件”。手动填写则仅使用输入顺序，错误输入不回退为自动选择。没有符合条件的波次不启动任务。自动清单提交后锁定，失败重试仍使用该任务原清单；不会因页面后续变化重新选取。

生成/打印波次支持手动“重试任务”（方案 B）。新版任务失败或部分完成后，按钮切换为重试；运行中仍可取消，主动取消不续跑。重试绑定原始任务输入，忽略当前页面改动，逐轮保留历史；“新建任务”用于主动放弃重试入口，不会自动排除页面上已经生成的订单，使用前需核对输入。

生成按原顺序跳过已确认波次，从未提交节点重新搜索并核对数量。生产提交前强制保存“结果未确认”检查点；提交后断线、未拿到波次号等情况拒绝盲目重试，需人工核对。已确认波次后的弹窗关闭失败可续跑剩余节点。记录损坏、保存异常、缺快照的旧任务不开放安全续跑。未续跑的新版失败任务会跨日保留，刷新及服务重启后可恢复入口。

打印保持并行度 5，每个成功 PDF 验证后保存独立副本及校验信息；重试复用有效副本，只补齐失败/未执行/文件损坏节点。只有合并失败且所有副本有效时，不启动浏览器、不重新打印。完整清单未齐全不发布合并文件；合并结果校验总页数后原子发布。文件丢失需重打时，WMS 可能增加重打记录。检查点 PDF 保存在项目 outputs 中，重试前不要清理；不会自动删除用户文件。

每轮重试使用关联的新任务 ID，原计划及累计确认结果不变。生成导出保留每轮版本，续跑文件名带 `-r2` 等轮次，旧下载不自动更新；打印合并文件使用唯一名称，避免覆盖其他轮次。重复点击或响应丢失后重发同一重试请求会返回同一轮任务，不重复建立执行实例。当前不做自动循环重试，也不自动查询 WMS 消除不明确结果。

USPS 细分首次默认开启，浏览器会记住开关。拆分模式长按 USPS-H 或 USPS-G 标签 3 秒关闭，长按 USPS 开启；移动或松手取消，任务执行中不可切换。固定顺序在原 USPS 位置排列 H、G，零订单仍沉底且默认关闭。两类独立分段，归并模式均进入普通；进化的普通照常吸收其关闭分段。

仅细分原识别为 USPS 的订单：按 2026-06-24 版本的 43 个 HAZMAT STC 精确匹配，支持 22/26 位 PIC、420 路由前缀及 Mod 10 校验；无法解析或数值型单号归 G。同一出库单号多行保持合并，任一行明确命中 H 则整单归 H。源数据不改写。切换时重建 USPS 分段及其选择，不沿用旧计划波次标记；其他渠道设置保留。

规划文档除“波次表”外保留 H/G 区分；“波次表”统一显示 USPS 并使用同色，但不合并波次，内部仍保留 H/G 对应关系，避免同名分段串填。归并或吸收后的订单按普通显示。

- **监听地址**：默认 `127.0.0.1`；可用 `--ip` / `HOST` 改地址，`--port` / `PORT` 改端口，命令行参数优先。本项目主要在本机使用，默认值即可；
- **运行中不要重启服务**：任务记录会保存到本地；重启会把未完成任务标为中断，保留已确认结果，不自动重跑 WMS 操作。执行结束后会释放后台执行对象，但不会因此删除任务结果、波次记录或导出文件；
- **浏览器会话安全**：`data/browser-profile/` 含生产登录态，不要打包分发，迁移机器时建议重新登录；
- **生产操作确认**：所有生产工作流都要求前端显式确认（`confirm_production: true`），同一时刻只允许一个活动任务；
- **下载目录**：WMS 下载文件默认落在 `downloads/`，规划 Excel/PDF 默认在 `outputs/`；点击网页下载时，另存位置由 Safari/Chrome 自身下载设置决定，后端不再复制到第二个目录；
- **生成波次容错**：若某分段部分订单被临时取消（待处理+已取消=分段订单数），不会跳过该分段，而是黄字提示后继续；订单回滚后可重新导入订单文件并重新生成；
- **中途停止的规划导出**：生成任务取消或失败后，页面会等待任务结束，再按提交时的快照保存完整九表规划文件；仅填入本次已确认的波次号，其他波次号留空，即使零完成也保留规划。页面离线期间结束的任务，在重新打开页面后恢复导出（需保留任务记录和快照）；保存失败可点击重试，同一任务只保存一份文件，不重新执行 WMS。没有快照的旧任务只保留日志，不借用当前页面的订单导出；
- **1000条/页**：自动化会先检查当前每页条数，已是 1000条/页 则不再重选；
- **开机自启（可选）**：用 LaunchAgent/plist 把 `start.sh` 注册为登录项即可，服务进程不依赖终端会话。
- **启停身份核对**：`start.sh` 与 `scripts/service_identity.py` 配套使用，数字 PID 文件旁会保存本次启动身份。停止/重启只接受项目、完整端口、命令和启动时间均匹配的进程；旧版缺少身份记录的活跃服务不会自动接管，升级前需按原启动方式正常停止，不能只删除 PID 文件。

## 测试

WMS「渠道拆分」模板需包含“推荐拣货库位”（至少 13 个已选项）。每次下载后，后端按出库单号关联“出库单”和“拣货库位明细”，按实际 SKU 对齐数量、库位，合并成一张“出库单”后才交付分析。原订单字段保持，重复单号/SKU 列不再输出；每个 SKU 后附出库数量及推荐库位。订单集合、SKU 集合或总件数不一致时停止交付并保留原下载。

截单预导出、增量和恢复下载共用上述步骤，最终截单文件保留合并的 SKU 数量/库位列。同号订单以增量整行覆盖，避免旧 SKU 或旧库位残留。旧的单表文件仍可导入规划；本次功能不会改写过去已交付的文件，也不会把库位额外复制到波次规划 Excel。

维护代码前可先阅读[源码导览](docs/CODE_GUIDE.md)，了解模块职责、订单统计口径、任务检查点及文件保存边界；关键实现旁有对应注释。

## 配置与环境变量

### `config/automation.json`

- `target_url` / `template_name`：导出工作流的订单页地址与模板校验；
- `wave_picking` / `wave_printing`：拣货与打印工作流的页面选择器、并发数、超时；
- `wave_generation`：生成波次工作流——搜索栏选择器、每页条数、多项搜索单次上限（700 行）、波次号格式、超时；`search_verify_wait_ms`（搜索数量核对短窗等待，默认 4000ms）。

配置在服务启动时读取；任务提交限制与实际执行共用这一份配置。修改 JSON 后需重启
服务生效，不会在运行中只更新提交校验而留下旧执行配置。

### 环境变量（均可选，默认值见 `backend/app/core/config.py`）

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `HOST` | 源码启动监听地址 | `127.0.0.1` |
| `PORT` | 服务端口 | 8000 |
| `WMS_AUTOMATION_CONFIG` | 配置文件路径 | `config/automation.json` |
| `WMS_BROWSER_PROFILE` | Chrome 会话目录 | `data/browser-profile` |
| `WMS_BROWSER_CHANNEL` | 浏览器通道 | `chrome` |
| `WMS_HEADLESS` | 默认是否无头 | `false` |
| `WMS_DOWNLOADS_DIR` | WMS 下载目录 | `downloads` |
| `WMS_OUTPUTS_DIR` | 导出/打印产物目录 | `outputs` |
| `WMS_FRONTEND_DIST` | 托管页面目录 | `frontend/dist` |

以上目录默认值针对源码启动。macOS `.app` 默认将下载放在
`~/Library/Application Support/WMS自动化控制台/downloads/`，规划 Excel/PDF 放在同级
`outputs/`，不写入应用包；显式环境变量仍可覆盖。旧文件不会被自动迁移或删除。

## 安全说明

- 生产操作需显式确认；同一时刻仅允许一个活动任务；
- 波次号/出库单号仅允许字母、数字、下划线、连字符，防止注入与歧义匹配；
- 导出与打印文件只能从项目 `outputs/`、`downloads/` 目录读取，接口带目录白名单校验；
- 服务默认监听 127.0.0.1；当前主要在本机运行，无需调整监听地址；
- 浏览器 profile、下载文件、波次记录均属敏感数据，备份或迁移时注意保管。

## 生成后跟随打印

“生成波次”按钮右上角的打印图标是独立开关，默认关闭，浏览器记住选择。点击主体仍只选择任务，点击“开始任务”才执行；开关在任务提交时锁定。

开启后，全部分段生成成功、原提交计划的 Excel 保存成功且浏览器清理完成，才自动启动打印。打印仅使用本次提交计划中的单件和混件波次，顺序与原波次表一致，不受手填打印范围或后续表格调整影响。打印沿用并行度 5，最终在日志中提供规划 Excel 和合并 PDF 两个文件。

生成失败、部分完成或取消时仍保存已有规划信息，但不跟随打印；通过“重试任务”完成剩余生成后可继续衔接。打印失败只重试打印，不重新生成波次。等待中的跟随打印可在日志取消；已经启动时使用打印任务的取消按钮。

规划 Excel 仍由前端生成，因此需要保持页面打开至保存完成；关闭后重新打开页面可从提交快照恢复保存。打印任务创建后由后端运行，刷新不会重复创建。服务仍需保持运行，电脑不能休眠。

## 单件分段与生成前检查

“爆品容量”仅控制爆品，保留原有单 SKU 超容量及超过 700 单的拆分规则。“单件”参数为单件分段数，默认 1；支持统一和单渠道调整。单件按 SKU 订单数降序、同数量按 SKU 排序，复用多件的连续均衡算法；同一 SKU 不拆散，空分段不生成，段数超过 SKU 数时只生成实际非空段。全量吸收档位下单件进入混件池，此参数暂不影响独立单件分段。

调整单件段数后，受影响的单件分段重新勾选，渠道总开关保持不变；进化普通渠道重新计算吸收，内容发生变化的普通分段也重新勾选。新规划不继承旧波次标记；已提交任务和重试仍使用原计划快照。

单件分段不自动增段来适应 WMS 上限。生成前对整批激活分段检查单段订单数（默认 700，以后端配置为准）和跨分段订单号重复，任一不合格则整批不启动。增加单件分段数后可重新提交；查看和导出规划不受此上限限制。生成执行器也在打开浏览器前检查，避免旧任务重试时先执行部分分段。
