# B3 第二切片 — 收尾异常与单机重复启动

验收日期：2026-09-07。范围：A11、A13 的单机工具可靠性部分。源码与离线回归完成；未访问真实 WMS、未启动生产浏览器、未重启当前服务、未提交或推送 Git。

## A11：业务结果与收尾分开

- 生成波次：提取号码后先通过原有逐段确认事件保存结果，再关闭结果弹窗。关闭失败不会抹掉该号码，也不会重复记成一段生成失败。若还有剩余分段，标明未执行并停止；最后一段关闭失败仅附警告，不改已确认的成功结果。
- 订单下载：仍使用 Playwright 下载事件和 save_as。保存成功后的任务中心关闭异常不阻止返回文件路径；没有增加重复导出、独立下载会话、额外落盘检测或固定等待方案。
- 已知导出失败、等待超时、任务列表读取失败及取消，不被普通任务中心关闭异常覆盖。尚未正式提交前，读取快照成功但弹层关闭失败，仍阻止继续提交。
- 打印：关闭打印页面、渲染页面及临时文件清理异常不会覆盖已保存 PDF 或原始打印失败。临时文件清理故障记录警告，不为了掩盖故障而再打印。
- 四种工作流统一处理浏览器上下文和 Playwright 驱动退出异常：普通收尾错误记警告，保留返回结果或原业务异常。取消仍传播，不一概吞掉异常。
- 工作流结果携带 warnings；JobManager 将尚未显示的警告补入日志。仅有收尾警告时状态仍是 succeeded，完成事件为 completed_with_warnings，避免已下载文件失去既有自动导入资格。失败数量造成的 partial 规则保持不变。

清理时不再调用可能抛错的进度回调来报告自身错误。作用域内的警告由列表收集，子任务继承同一收集范围；作用域退出后恢复，不串入下一任务。后端日志也保留清理异常堆栈；如果工作流本身失败而没有返回结果，原业务原因仍是主错误。

## A13：先占用，再恢复；先收尾，再释放

新增 `core/runtime_lock.py`，使用现有支持平台 macOS/Linux 的标准库文件锁，无新依赖、数据库或跨机器协调框架。

- 后端 lifespan 在创建 JobManager 前，先取得数据目录和规范化后的浏览器配置目录两个独占锁。因此第二实例不能先恢复/改写第一实例的 jobs.json，也不能先执行导出前的浏览器下载状态修复。
- 独占与端口无关；直接启动后端、桌面入口及启动脚本最终进入同一生命周期。不同 profile 但共用数据目录仍互斥；数据目录和 profile 均独立才允许并行启动。
- 软链接别名不能绕过。按固定顺序尝试非阻塞获取；部分获取后失败会释放已取得的锁。
- 锁依据打开的文件描述符，而不是文件是否存在或 PID 文本。锁文件不删除，避免换 inode 绕过；进程退出由操作系统释放。不会自动杀死原服务或删除 Chrome 的 Singleton 文件。
- 服务退出先取消并等待后台任务、浏览器收尾和最后保存，再释放占用；退出过程再次收到取消，不提前解锁。
- 补充复现并修复：用户先取消任务、随后退出服务，第二次 cancel 原先会打断已开始的浏览器收尾。现在不重复向已取消中的执行器发取消信号；取消请求自身断开也不会连带打断执行器收尾。

边界：这是遵守本项目入口的本机进程互斥，不控制手动用同一 `--user-data-dir` 打开的 Chrome、不支持用多机器共享目录协调服务。当前旧版服务尚未采用这些锁，升级时必须先正常停止旧版再启动新版，不能以另开一个端口验证生产配置。未改变历史下载状态修复的适用平台/版本；没有足够现场证据时不删除或收窄已有修复。
